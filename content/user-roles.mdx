# User Roles

<Callout type="warning">
    This page is not linked from the docsite navigation or from any other page.
    It documents VectorVerify's internal permission model for maintainers, not
    end users.
</Callout>

VectorVerify does not use a tiered access-level system. Each user is granted a
set of independent capability flags by a program administrator. Which flags a
user has determines which sections of the app they can open and which extra
tools appear in their account menu.

## Capability flags

| Flag                                      | What it controls                                               |
| ----------------------------------------- | -------------------------------------------------------------- |
| `sites.viewSiteMetadata`                  | Access to Operations                                           |
| `sites.writeSiteMetadata`                 | Access to Review                                               |
| `annotations.viewAndWriteAnnotationTasks` | Access to Annotation, and to the Operations User Analytics tab |
| `devMode`                                 | Developer-only tools — see below                               |

A user can hold any combination of these flags. Someone with only
`sites.viewSiteMetadata` can open Operations but not Review or Annotation.
Someone with both `sites.viewSiteMetadata` and `sites.writeSiteMetadata` can
open both.

Two additional `sites`-scoped fields exist on the permissions schema but do not
currently gate access to anything: `pushSiteMetadata` is declared but unused
anywhere in the app today, and `canAccessSites` (a list of sites) scopes _which
sites' data_ a user sees within a page they already have access to — it does not
control _whether_ they can open that page.

## Developer mode

Accounts with `devMode` enabled see additional tools in the account menu:

- A **Developer Status** badge
- **Raw Data Export**
- **User Analytics** — an account-menu dialog showing user activity data

This account-menu **User Analytics** dialog is unrelated to the **User Analytics
tab** inside Operations. The Operations tab is gated by
`annotations.viewAndWriteAnnotationTasks`, not `devMode` — any user with that
flag sees the tab regardless of developer status.
