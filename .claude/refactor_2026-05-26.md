## H. Simplify `runExport` to iterate the selection Map directly

After D and G, the loop becomes a straight nested iteration with no array buildup, no encoded keys:

```ts
async function runExport(siteIrsData: Map<number, SiteIrsData>) {
    setExportStatus('exporting');
    setExportResultsByMonth(new Map());

    let totalToExport = 0;
    for (const siteIds of selectedSites.values()) totalToExport += siteIds.size;

    const newResultsByMonth = new Map<string, Map<number, ExportSiteStatus>>();
    let completedCount = 0;
    setExportProgress({ completed: 0, total: totalToExport });

    try {
        for (const monthKey of [...selectedSites.keys()].sort()) {
            const [yearString, monthString] = monthKey.split('-');
            const year = Number(yearString);
            const month = Number(monthString);
            const monthResults = new Map<number, ExportSiteStatus>();
            newResultsByMonth.set(monthKey, monthResults);

            for (const siteId of selectedSites.get(monthKey)!) {
                const irsData = siteIrsData.get(siteId) ?? { siteId, wasIrsSprayed: false };
                let siteExportStatus: ExportSiteStatus;
                try {
                    const apiResult = await mutateAsync({
                        queryParams: { year, month, district, siteIds: String(siteId) },
                        body: { irsData: [irsData] },
                    });
                    if (apiResult.ok) {
                        const resultsForSite = apiResult.data.results.filter(r => r.siteId === siteId);
                        siteExportStatus =
                            resultsForSite.some(r => r.status === 'failed') ? 'failed'
                            : resultsForSite.some(r => r.status === 'success') ? 'success'
                            : 'skipped';
                    } else {
                        siteExportStatus = 'failed';
                    }
                } catch {
                    siteExportStatus = 'failed';
                }
                monthResults.set(siteId, siteExportStatus);
                completedCount += 1;
                setExportProgress({ completed: completedCount, total: totalToExport });
                setExportResultsByMonth(new Map(newResultsByMonth));
            }
        }
    } finally {
        setExportStatus('done');
        await queryClient.invalidateQueries({ queryKey: sessionKeys.root });
    }
}
```

## Implementation rules (reference)

These govern how the cleanup is carried out, not what it produces. Every item above respects:

- **Descriptive variable names.** Every identifier conveys what it holds. Not `value`/`v`/`q`/`first` — use `prerequisiteExpression`/`predicateValue`/`referencedQuestion`/`firstReferencableQuestion`. If a reader has to consult the type to understand the variable, the name is wrong. Applies to props, locals, callback parameters, destructured pieces.
- **Minimal implementation.** Build only what the current step requires. No speculative scaffolding, no "we'll probably want X later," no helper layers waiting for a second consumer, no flag-guarded experimental code paths. Three similar lines beats a premature abstraction.
- **No intermediate types outside the main domain models.** Contract schemas under `src/api/<resource>/validation/` are the only named data shapes. Components and utilities operate directly on those types — no editor models, no flattened intermediate views. React-state pieces stay as primitive destructured fields without naming the composite. Component props interfaces are fine; they describe a component's surface, not a reusable data shape.
- **Utility functions only when absolutely necessary.** A util in `src/features/<feature>/utils/` earns its place only when the alternative is real duplication. Bar: ~3 call sites across ≥2 files of non-trivial logic. A 3-line helper used once is inlined. A helper used twice within a single file is inlined or expressed as a closure inside the consuming function. No speculative utilities, no `parse`/`serialize` pairs, no factory functions, no module-level helpers defined inside component files.
- **No overengineering.** If the natural expression is a 5-line inline computation, that's the expression. If the natural expression is a 15-line cross-file switch, that earns a util. Nothing in between gets abstracted. Premature flexibility (options parameters, hooks-as-props, generic wrappers) is rejected by default and only added when the second real consumer materializes.
